# 山竹智能体后台任务运行架构设计

## 目标

借鉴 Codex App Server 的 Thread、Turn、Item 生命周期，把山竹现有 Agent 改成“后台持有任务，页面订阅状态”的结构。用户切换 Wiki、设置、对话或项目时，正在运行的任务不会因为页面变化而丢失；回来后可以补齐进度、引用和最终回答。

本次不把 Codex App Server 设为山竹的唯一引擎。Codex CLI、Claude CLI、API 模型和本地模型最终共用山竹自己的 Agent 运行契约，现有 Rust AgentRuntime、知识库、RAG、网页搜索、Skills、权限与文件工具继续保留。

## 产品原则

- 后台是运行状态的唯一真相，前端只负责发起任务、订阅事件和展示结果。
- 一次用户请求只能产生一份最终回答，禁止后端生成后再由前端重复调用模型。
- “联网搜索默认开启”只表示工具可用，不表示每轮都必须联网；工具是否执行由本轮意图和证据需求决定。
- 引用不等于回答。没有非空正文或已确认生成物时，任务不能标记为成功；待用户输入必须保持独立的 `waitingInput` 状态。
- 应用关闭后按现有产品约定终止任务；下次启动将未完成任务显示为“已中断”，不在后台自动续跑。

## 不采用的方案

### 不直接用 Codex App Server 替换全部 Agent

Codex App Server 很适合 Codex 自己的认证、模型和工具生态，但山竹还需要支持 Claude CLI、第三方 API 和本地模型。直接替换会让非 Codex 模型成为第二套流程，并让山竹依赖仍在实验阶段的动态工具接口。

### 不复制完整 JSON-RPC 和代码 Agent 功能

不复制 Codex 的 Git/worktree、代码补丁、终端沙箱、远程主机、账号路由、多智能体、任务分叉、V1/V2 兼容层或原始推理流。山竹只借用与知识助手直接相关的任务生命周期、事件重放、中断和最终结果规则。

## 核心模型

### Thread

一段用户对话。继续使用当前 `conversationId/sessionId` 作为 Thread 标识，不再创建第二套会话编号。

### Turn

用户在某个 Thread 中提交的一次请求。每个 Turn 由后台生成稳定 `turnId`，并包含：

- `projectId`
- `threadId`
- `turnId`
- `status`: `running | waitingInput | completed | interrupted | failed`
- 当前事件序号 `seq`
- 最终聚合结果或错误
- 创建、更新和完成时间

同一 Thread 第一阶段只允许一个活动 Turn，避免多个任务同时改写同一对话状态。不同 Thread 可以独立运行。

### Item

Turn 内的一次可观察工作单元。第一阶段支持：

- `agentMessage`
- `wikiSearch`
- `sourceSearch`
- `graphSearch`
- `webSearch`
- `skillRead`
- `fileWrite`
- `shellCommand`
- `userInput`

每个 Item 都有稳定 `itemId`；工具调用同时有稳定 `callId`，状态为 `started | completed | failed | declined`。重复执行同一个工具时，前端能够正确配对、去重和重放。

## 后端运行契约

### 发起任务

`agent_start_turn_stream` 接收当前请求后立即返回 `projectId + threadId + turnId`。真正的 Agent 工作继续在 Tauri 后台运行，不依赖 ChatPanel 是否挂载。

后台在开始执行前创建 Turn 记录；如果创建失败，不启动模型或工具。

### 事件格式

桌面事件统一为：

```text
{
  projectId,
  threadId,
  turnId,
  seq,
  timestamp,
  event
}
```

`seq` 在每个 Turn 内严格递增。高频文本增量可以合并，但 Item 完成、最终回答、失败、中断和用户输入请求属于关键事件，不能丢弃。

### 查询与补漏

新增只读查询 `agent_get_turn(projectId, threadId, turnId, afterSeq)`，返回 Turn 快照及指定序号之后的事件。

前端首次进入对话、重新进入对话、监听重连或发现序号跳跃时调用该查询。实时事件和历史事件必须进入同一个 reducer，保证“运行时看到的内容”和“重新打开后看到的内容”一致。

### 终止任务

`agent_cancel_turn` 必须携带明确 `turnId`。后台只中断匹配的活动 Turn，重复中断安全返回当前终态。任务进入 `interrupted` 后，不再启动新工具；晚到结果不再写入最终状态。

### 完成与持久化

最终顺序固定为：

1. 完成 Agent 生成与工具收尾。
2. 验证最终结果。
3. 原子保存用户消息、最终正文、引用、工具 Item、文件变化和终态。
4. 广播携带完整聚合结果的 terminal 事件。

`completed` 必须满足以下任一条件：

- 存在非空最终正文；
- 用户请求的是生成文件，并且后台确认生成物存在。

如果流式增量为空，但同一次模型请求的聚合响应存在有效正文，后台使用该聚合响应作为兜底，不能再次调用模型。两者都为空时将 Turn 标记为 `failed`，显示真实错误，禁止创建空白 assistant 消息。需要用户补充信息时，Turn 保持 `waitingInput`，收到对应输入后继续原 Turn。

## 模型提供方统一

保留 `AgentRuntime` 作为总管，模型接入只负责生成能力。每个提供方声明：

- 是否支持文本流式输出
- 是否支持图片输入
- 是否支持精确取消
- 是否支持结构化工具调用
- 是否支持运行中追加要求

本轮可用能力取以下三者交集：

```text
山竹产品与安全规则 ∩ 模型真实能力 ∩ 本轮用户意图
```

Codex CLI 已具备 Rust 后端 Agent Provider，第一阶段直接进入统一后台流式链路，删除前端第二次生成。Claude CLI 在第二阶段补充后端适配器；完成前保留其现有输出能力，但不得再产生双重生成或空白成功消息。

## 工具与证据策略

- “我的产品、我们的资料、根据知识库、根据我之前保存的内容”等个人或项目请求，先查本地 Wiki、原始资料和图谱。
- 本地证据不足时询问一个简短澄清问题，不能用通用网页教程替代用户自己的事实。
- “最新、新闻、市场、竞品、网上、联网”等外部或时效请求才自动调用网页搜索。
- 明确要求“结合我的资料和市场信息”时，允许本地与网页检索同时使用，并在引用中区分两类来源。
- “检索到的资料”与“最终答案实际采用的引用”分开记录；只把实际支撑答案的来源显示为主要引用。

## 前端状态与交互

ChatStore 不再只有一份全局 `isStreaming/streamingContent`，而是按 `threadId + turnId` 保存活动任务状态。

前端 reducer 负责：

- 按 `seq` 去重和补齐事件
- 累积流式正文
- 更新 Item 的开始、完成和失败状态
- 收集引用与文件变化
- 使用 terminal 聚合结果校正本地状态

人性化提示继续由真实状态映射：

- Turn 已接收：`收到啦～`
- Wiki/资料检索：`我看看你的资料嗷～`
- 网页检索：`我去看看网页信息～`
- 模型整理答案：`正在整理重点～`
- 已有最终正文增量：`快完成啦～`

提示语可以从预设词条轮换，但不能让模型随机编造尚未发生的操作。

切换页面或对话只取消订阅，不取消 Turn。返回时通过 `agent_get_turn` 补齐。切换项目后，旧 Turn 仍严格绑定旧 `projectId`；前端应明确显示旧项目任务状态，任何文件写入继续受后台项目边界校验。

## 异常处理

- 模型/API/CLI 失败：Turn 为 `failed`，保存失败阶段、原始可读错误和已完成 Items。
- 监听断开：后台继续；前端重新订阅并按 `afterSeq` 补漏。
- 后端 panic 或任务异常退出：运行外壳捕获并生成 terminal failed，不能只靠前端等待超时。
- 用户中断：Turn 为 `interrupted`，保留已产生的正文、引用、工具结果和文件变化，并标注结果不完整。
- 项目切换：不让旧事件写入新项目或新对话；不使用全局 streaming 状态互相覆盖。
- 同一 Turn 的晚到事件：终态后忽略非关键增量；任何新文件写入必须在执行前再次检查取消状态。

## 数据边界

后台 Turn 记录是运行过程的权威来源；用户可见聊天记录是终态投影，不再由前端和后端各自保存一份互相矛盾的历史。

第一阶段沿用项目内 `.llm-wiki` 数据目录，新增轻量 Turn 状态文件。只保存恢复 UI 所需的状态、事件、引用和结果，不保存模型原始推理过程。事件数量和文本增量需要有上限，完成后可合并高频 delta，保留关键 Item 和终态。

## 分阶段实施

### 第一阶段：修复当前核心链路

- 让 Codex CLI 与 API/本地模型走统一后端流式 Agent。
- 删除 Codex CLI 的前端第二次生成。
- 增加非空最终答案硬校验。
- terminal 事件携带完整聚合结果，并在持久化后发送。
- 增加后台 TurnStore、稳定 ID、事件序号、快照查询和精确中断。
- 前端使用 per-turn reducer，支持切页、切对话后恢复显示。

### 第二阶段：统一提供方与交互

- 增加 Claude CLI 后端适配器。
- 增加提供方能力声明和统一工具策略。
- 增加运行中补充消息；必须携带 `expectedTurnId`，支持的提供方立即加入当前 Turn，不支持的排到当前 Turn 完成后。
- 将待用户输入、批准和继续执行绑定原 Turn，而不是拼接提示词新开无关联任务。

### 第三阶段：按真实需求扩展

- 长对话上下文压缩及可见状态。
- 同一会话的受控任务队列。
- Codex 原生 App Server 适配器试验；仅在动态知识库工具接口稳定且实际收益明确时启用。

不在当前范围内实现多智能体、远程运行、跨进程继续执行或代码 Agent 工作区。

## 验收标准

1. 使用 Codex CLI 提问一次，只产生一次最终生成，不再重复启动第二次聊天生成。
2. “根据我的产品写介绍”命中山竹知识库；未明确要求外部信息时不搜索网页教程。
3. Agent 运行时切到 Wiki、设置或另一段对话，任务继续；返回后进度、引用和答案完整且不重复。
4. 点击停止只中断对应 Turn，停止后没有新工具调用或晚到文件写入。
5. 空正文加引用不能成为成功消息；用户一定看到有效回答、待输入提示或明确错误。
6. 工具重复调用时，开始、完成、引用和错误能按 `itemId/callId` 正确配对。
7. 项目切换期间旧 Turn 不会写入新项目，不会清除新对话的运行状态。
8. 应用关闭后任务终止；下次启动将未完成 Turn 标记为已中断。
9. Codex CLI、API 模型和本地模型在第一阶段使用相同的 Turn 终态语义；Claude CLI 在第二阶段达到相同语义。
10. 外部引用可点击，本地引用可在应用内打开；主要引用只包含实际支撑回答的来源。

## 验证方案

- Rust 单元测试：Turn 状态转换、事件序号、终态幂等、空正文失败、精确中断、晚到事件拒绝。
- Rust 集成测试：后台流式 Turn 完成后可查询和重放；持久化先于 terminal 事件；项目隔离。
- 前端测试：同一 reducer 同时处理实时和补漏事件；切换对话不清除其他 Turn；空正文不落消息。
- 提供方回归：Codex CLI、一个 API 模型和 Ollama 各完成知识库问答；Claude CLI 在第二阶段加入。
- 桌面真实流程：运行中依次切换 Wiki、设置、其他对话和原对话，验证任务不中断、状态不串线、答案可恢复。
